LiveBuffer
Link copied to clipboard
class LiveBuffer(registry: InterfaceRegistry, val windowS: Int = 60, maxBytes: Long = 200L shl 20)

The latest data that arrived on some topics, in memory (like a video's "instant replay"): to go back in 3D without having recorded a bag. Keeps the last windowS seconds without exceeding maxBytes; for the "latched" ones (/tf_static, the map, the robot description) always the latest, even if it is older. dump writes it as MCAP, which plays back with the usual time bar.

object Lz4Frame

LZ4 decompressor in "frame" format (https://github.com/lz4/lz4/blob/dev/doc/lz4_Frame_format.md), the one MCAP uses for "lz4" chunks. Pure Kotlin, no native code. Does not check the xxHash checksums (the MCAP chunk already carries its own CRC32).

McapWriter
Link copied to clipboard
class McapWriter(out: OutputStream, chunkSize: Int = DEFAULT_CHUNK_SIZE, profile: String = "ros2", library: String = "vizmini2", rosDistro: String? = "jazzy", fileName: String = "vizmini2_0.mcap") : Closeable

Writes an MCAP file in streaming fashion, as rosbag2 (Jazzy) does with -s mcap: header with "ros2" profile, messages grouped in uncompressed chunks (~1 MiB) followed by their MessageIndex, and on close a summary with Schema, Channel, Statistics, ChunkIndex and MetadataIndex plus their SummaryOffset and the Footer. This way ros2 bag info / ros2 bag play read it without scanning the file.

PlaybackClock
Link copied to clipboard
class PlaybackClock(wallNs: Long, bagNs: Long, rate: Double)

Playback clock: at which instant of the phone's clock each bag message is due. When the speed changes it is re-anchored at the current position, so what has already played is not reinterpreted with the new one (previously, going from 1x to 2x released a sudden burst of messages and going to 0.5x stalled).
