DesktopAccount
Link copied to clipboard
object DesktopAccount

The VizMini2 account on the PC: the same Firebase one as on the phone (Google, Microsoft, GitHub or email), and the robot profiles synced in Firestore (users/{uid}/profiles, same format as Android). Firebase has no desktop SDK: everything goes through its REST APIs. Google, Microsoft and GitHub open in the browser with a local page (http://localhost, an authorized domain by default) that uses the Firebase web SDK and returns the session to the PC.

FfmpegVideoDecoder
Link copied to clipboard
class FfmpegVideoDecoder : VideoDecoder

H.264/H.265 on the PC with the system's ffmpeg (apt install ffmpeg; $VIZMINI2_FFMPEG to use another one): the elementary stream goes in through stdin and each frame comes out as a BMP (which carries its size, so a change of resolution needs nothing special). So that it does not hold frames back: the low-delay options (but not -fflags nobuffer, which throws away the probed data and with it the first key frame), slice threads instead of frame threads (each one holds a frame), and each frame's access unit delimiter moved from its start to its end (ffmpeg's stream parser only knows that a frame has ended when the next one starts).

LinuxDesktopEntry
Link copied to clipboard
object LinuxDesktopEntry

The desktop entry when the app is not installed from the .deb (for example ros2 run vizmini2 vizmini2): without one, GNOME and KDE show the Java class name and a generic icon in the top bar and the dock. The first time, it writes ~/.local/share/applications/vizmini2.desktop (Name VizMini2, the logo, StartupWMClass=vizmini2, and the launcher of this installation) and the logo next to it; it also adds VizMini2 to the applications menu. The .deb brings its own entry (see fixDebDesktopEntry in desktopApp/build.gradle.kts), so then nothing is written.
