Architecture

One code base, two apps: almost everything the user sees is shared between Android and the desktop.

Folder

What it is

core/

Shared logic in plain Kotlin/JVM, unit tested: the ROS connection and its middlewares, the dynamic message codec, the models of every tab (plots, alerts, controllers, maps, MoveIt, Nav2…), bags, profiles and the texts (i18n).

ui/

Shared Compose screens (most tabs, the catalog, dialogs, import and export), compiled into both apps.

rviz3d/

The 3D view on Filament: displays, tools, interactive markers, meshes.

app/

The Android app: activities and fragments around the shared screens, the background connection, demo mode, notifications, screen recording, Firebase (account, crash reports).

desktopApp/

The desktop app (Compose for Desktop): the window and sidebar, file dialogs, ffmpeg video decoding and recording, desktop notifications (notify-send or the system tray), the .deb and the .msi, and the end-to-end tests.

ros/vizmini2/

The ROS 2 package: colcon build runs Gradle and ros2 run vizmini2 vizmini2 starts the app.

tools/

Test servers (fake robot, Nav2, MoveIt with the Panda, ros2_control, video, maps…), CI and release scripts, the Ubuntu 20.04 build of the desktop natives, the Windows natives (tools/desktop-natives) and the list of prebuilt binaries (tools/prebuilt).

docs/

This manual (Sphinx, English and Spanish).

How it talks to ROS

  • DDS with Fast DDS (through jros2), built for Android (arm64, x86-64…), Linux and Windows. The app is a DDS participant like any ROS 2 node: no bridge, no agent on the robot. Cyclone DDS robots interoperate over the wire.

  • Messages are dynamic: the interface definitions (app/src/main/assets/ros_interfaces.txt, generated by tools/gen_ros_interfaces.py) are parsed at run time and encoded and decoded with a CDR codec, so any bundled type can be used without generated classes. Where a message changed between distros (MoveIt, ros2_control), the app carries each version’s definitions and detects which one the robot uses.

  • Zenoh (rmw_zenoh’s key expressions and attachments) and foxglove_bridge (its WebSocket protocol) are alternative transports behind the same interface, for networks where DDS discovery does not work.

The 3D view

Filament renders the scene on both platforms (OpenGL ES on Android, OpenGL on the desktop). On the desktop it renders off-screen and the frame is shown inside Compose. TF is a time-indexed tree; displays subscribe through the same connection as the rest of the app.

Desktop natives

The desktop app’s native libraries (Fast DDS, the Filament JNI, a small X11 helper) are built for Linux in an Ubuntu 20.04 user-namespace root (tools/compat) so they need glibc 2.31 at most; Fast DDS links libstdc++ statically and hides it, so it does not clash with the JVM’s. The Windows ones are built with MSVC by the Windows natives workflow (tools/desktop-natives). The Java runtime is bundled (jlink), so the .deb and the .msi need neither Java nor ROS.

The Fast DDS and Filament natives and jros2 for Android are not in git: they live in the repository’s prebuilt release and the build downloads them (tools/prebuilt). Each package only carries its own system’s natives: the .deb, the .tar.gz and the ROS package the Linux ones; the .msi and the .zip the Windows ones.
